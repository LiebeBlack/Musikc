Guía para personas usuarias, desarrollo local y compilaciones automatizadas. El instalador final de una versión debe descargarse desde el release publicado en GitHub.

01 / USO NORMAL

Instalar desde
un release.

  1. 01Abre el último release del repositorio. Descarga el setup x64 publicado o el ZIP portable.
  2. 02Comprueba el hash SHA-256 contra SHA256SUMS.txt si está adjunto al release.
  3. 03Ejecuta el instalador firmado/publicado por el proyecto y selecciona el DAC en Hardware.
  4. 04Usa WASAPI Exclusive solo cuando el DAC y el driver acepten el formato deseado.
Ir al release de GitHub ↗

02 / DESARROLLO LOCAL

Entorno aislado.

El bootstrap verifica Windows x64, prepara .venv, instala los paquetes fijados e intenta obtener los binarios nativos. Mantén las dependencias dentro del entorno virtual del proyecto.

POWERSHELL / CLONAR Y PREPARAR
git clone https://github.com/OWNER/REPOSITORY.git
cd REPOSITORY
python setup_env.py
python setup_env.py --run

El nombre del repositorio se completa al publicar la página, y el botón de copiar usa siempre la dirección vigente. setup_env.py --check ejecuta diagnósticos; --repair reconstruye el entorno; --dev instala herramientas de pruebas y build.

04 / BUILD LOCAL

Pruebas antes
de empaquetar.

COMANDOS DE VALIDACIÓN
python -m pip install -r requirements-dev.txt
python -m compileall -q src main.py setup_env.py scripts
python -m ruff check src main.py setup_env.py scripts tests --select F,E9
python -m pytest -q tests

El build completo con python scripts/build.py ejecuta tests, crea el ejecutable y el ZIP portable. Para producir el instalador también se necesita ISCC.exe de Inno Setup 6.

05 / AUTOMATIZACIÓN

Dos workflows.
Dos trabajos claros.

WorkflowSe activaResultado
build.ymlPush a main/master, PR, tag v* o manualTests Windows, freeze, ZIP, instalador y artefactos
pages.ymlCambios de docs/workflow en main/master o manualValidación de docs y publicación GitHub Pages

El workflow de Pages publica únicamente desde main/master. Requiere Pages → Build and deployment → GitHub Actions en la configuración del repositorio y los permisos pages: write e id-token: write.

06 / RELEASE

Un tag dispara
el empaquetado.

  1. 01Actualiza la versión en configuración, pyproject y recursos del instalador.
  2. 02Ejecuta la suite y confirma que el build local pasa.
  3. 03Sube cambios a GitHub y crea un tag que empiece con v (por ejemplo v2.5.9).
  4. 04Espera a que build.yml termine; el release adjunta el ZIP portable, SHA256SUMS y setup si ISCC se instaló.

Si un runner no puede descargar herramientas nativas o una dependencia, el job debe fallar con el log visible; no se debe publicar un asset incompleto como release estable.
